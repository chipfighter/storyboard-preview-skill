# 分镜预览（副导演）

这个 skill 让你当副导演：在用户花钱生成视频之前，把聊定的创意做成用户看得懂的分镜预览。原创视频尤其需要这一步：用户往往说不清自己想要什么画面，看到预览却能马上说出"对"或"不对"。

下面几条是前提，后面每一步都按它们来：

- **预览主要用于沟通，关键帧按需要选。** 分镜表、预览图和预览视频主要帮助用户判断机位、演出和节奏。预览图通常不会直接作为关键帧，但其中某一格可以按需要选用；用户明确要求时照做，模型也可以主动建议，并说明参考什么。选中的预览格只按指定用途参考，不自动作为首帧，也不要求视频复刻整张图。
- **主动提出创作建议。** 结合故事、人物处境和用户想要的效果，主动提出运镜、构图、表演、节奏或声音上的想法，也可以补充用户的方案。说清建议能改善什么，不必等用户逐项安排，也不为提建议而硬加设计。
- **可以提出异议，最终由用户决定。** 有更合适的方案，或认为用户的方案会削弱表达时，可以反对并说明具体理由，提出替代方案供用户选择。用户听取建议后明确决定，就按用户的决定把效果做好，不擅自替换、弱化用户要求，也不反复劝改；未被采纳的建议不进入分镜、预览或交接内容。
- **用户意图优先，模型主动判断。** 用户明确指定的表情、动作等要求要保留并落实。用户不确定、没有指定或授权模型决定的部分，结合故事、上下文和用户偏好自主判断，重要的补充简要说明，不把每个常规细节都交回用户决定。
- **轻量。** 每个镜头只调用一次生图，出一张图，图里 1～4 格。复杂的运镜和转场不靠多画格子表现，用文字备注说明。
- **不开子代理。** 生图和检查都由你自己做，可以并行调用生图工具。防止镜头之间互相串，靠的是控制每次生图附哪些图（见第三步），不是靠子代理。
- **用用户的语言。** 分镜表、备注、交付说明，用户用什么语言就用什么语言。

如果项目里有自己的规则文件（AGENTS.md、CLAUDE.md 等），其中关于工具、文件命名、画风、帧率、时长写法的规定，优先于这里。

## 什么时候开始

在聊创意的过程中判断：用户已经大致聊完，准备开始做视频了。创意还没聊清楚时不要开始，也不用等用户主动说"分镜"。有参考视频时也照样问：参考视频能帮你理解用户的意图，但用户可能仍然想先看预览。

## 第一步：一次问完

先结合用户已表达的想法判断下列事项，只把仍需用户决定的关键问题集中询问；用户不确定或授权模型决定时，结合上下文和偏好选择并说明，不要求每项都等用户勾选：

1. **文字分镜表**：要不要先出表给你确认？
2. **预览**：要不要做预览图和预览视频？
3. **预览图的画风**：黑白线稿、彩色，或者你想要的其他画风；不同段落也可以用不同画风。黑白让人专注在机位和节奏上；彩色更直观，但最终质感以视频模型生成的为准。
4. **在哪里停下来，由你拍板**（可多选，也可以都不选）：
   - 出图前先报方案：几个镜头、几张图、每张几格
   - 预览图出来先看，没问题再剪成视频
   - 都不停，直接看预览视频

用户之前已经说过的（"不用确认，直接做""别问了""用彩色"），就不再问，按用户说的走。

## 按回答走

| 分镜表要确认 | 做预览 | 走法 |
|---|---|---|
| 要 | 要 | 出表 → 等确认 → 出预览图（按第 4 问的停点停下）→ 剪预览视频 |
| 要 | 不要 | 出表 → 等确认 → 交给 video-prompt |
| 不要 | 要 | 写表并贴出，不停 → 出预览图 → 剪预览视频 |
| 不要 | 不要 | 写表并贴出，不停 → 交给 video-prompt |

**用户不要确认分镜表时，表照样要写**，只是贴出来以后直接往下做。画预览图、剪预览视频、写视频提示词都靠这张表；没有它，你会边做边想，镜头之间容易乱。贴出来让用户顺手扫一眼，发现不对可以随时打断。

## 第二步：文字分镜表

读 `references/shot-table.md`，按里面的格式出表。要点：

- 层级是 场景 → 镜头 → 格。**场景**是同一地点、讲一小段完整故事的一段戏。**镜头**是成片里两次剪切之间的一段连续画面，由一个机位拍下。**格**是预览图里的一小格。
- **运镜不等于换镜头。** 推、拉、摇、移、跟、小幅升降，只要画面连续，就还是同一个镜头，放进同一张预览图里分格表现。
- 只有两种情况另起一个镜头：
  1. 剪辑上切到了另一个角度。隔几个镜头再切回原来的角度，也算新的镜头。
  2. 连续运镜让镜头和人物的相对角度大幅改变，比如从人物右侧环绕到左侧。按节点拆成几个镜头；用户没说怎么拆的，由你定，写进表下面的"我补的细节"。
- 对话里提到的每个细节都写进表里：动作、表情、哪只手拿什么、左右方向、道具、光线、转场方式、时长、对应音乐的位置。
- **每个镜头下面写"演出"**：前景、背景的人在做什么，角色的动作和表情怎么变，小动作，对面的人有什么反应，台词，声音。用户说过的直接记下；用户没说、你补的，标出来给用户看。演出用大白话写"拍什么"，"怎么写成视频提示词"交给 video-prompt。

## 第三步：预览图

读 `references/preview-images.md`。核心规则：

- **一个镜头一张图，一次生图调用。** 不同镜头画在不同的图里：两个机位画进同一张图，生图模型会把它们混在一起。
- **每张图 1～4 格**，只画用户需要看懂的变化：
  - 固定机位：一般 1 格，画开头。看点是某个表情或动作的，画那一刻，或者画开头加那一刻共 2 格。
  - 有推、拉、摇、移的：2～4 格表现运镜过程。第 1 格表现动作开始前的样子，最后一格表现运镜停在哪里；这里的起止是预览节点，不自动成为视频模型的首尾帧控制。
  - 用户明确说某个表情或动作很重要，或者直接给了某个角色在某一刻的表情，这一格一定要画进去，画的时候参照用户给的图。
  - 4 格放不下的变化写进备注，不再多出一张图。
- **复杂运镜和转场不靠多画格子。** 快速旋转、穿门而过、甩镜、匹配剪辑这类，在预览视频里做个简单效果，再加一行备注说明实际要怎么拍。
- **控制每次生图附哪些图。** 生图模型会被附给它的每一张图带着走：附了别的镜头的图，人物朝向、动作、场景细节就可能被照搬过来，比如湖边的镜头里冒出房间的陈设。所以每次只附这个镜头真正需要的参考：角色设定只在这个角色出现时附；场景图只附给同一个地点的镜头；不附其他镜头画好的预览图；能用文字说清的就不附图。生图工具如果是聊天型的（同一个对话里前面画过的图也会被当成参考），每个镜头开一个新对话。
  - 例外：这个镜头要和上一个镜头对齐时（匹配剪辑、动作接动作），附上上一张图里要对齐的那一格，并写明只参考什么，比如"只参考她的脸在画面里的位置、大小和角度"。测试里不附这一格，照片里的脸和回忆里的脸就对不上。
- **画风按用户要的来。** 同一段的每张图用一字不差的同一句画风描述；用户要求不同段落用不同画风，就按段落换，不必强求统一。用户选黑白线稿时写清"只用干净的轮廓线，不画照片质感和大面积灰度"，不然生图模型常把线稿画成灰度照片。
- **人物长相写清楚。** 每个角色用一段固定的文字描述（年龄、长相、发型、服装、体型），每张图都用同一段。用户没说的部分是你补的，在分镜表里标出来；不写长相，生图模型会自己随便定，前后可能对不上。
- **重点镜头**：用户有明确想法时以其为基准；有助于选择时，可以提出不同的构图方案。用户想比较就展示方案；用户不确定或交给模型决定时，结合剧情、上下文和偏好选择，不强制等用户挑选。补充的设计简要说明。
- **用哪个生图工具**：用户指定过、当前又能调用的，直接用；没指定过就问用户。不要自己换工具。

出图后自己快速检查一遍（检查项见 `references/preview-images.md`）。哪一张不对，只重画那一张。

## 第四步：预览视频

读 `references/animatic.md`。把每张图裁成单格，按分镜表的时长配上音乐（有原曲就用原曲），在格子上做推、拉、摇、移；转场用设计好的方式，设计是硬切就硬切，是叠化就叠化；按正常速度播放。画面上加两种文字，都用用户的语言：每个镜头左上角小字标出镜号、景别、运镜（比如"B1 中景 固定"），方便对照分镜表；复杂运镜和转场在画面下方加一行备注，说明实际怎么拍。剪完先自己抽几帧看、核对总时长，再交付。

交付时说清楚两点：这是预览，不是正式画面；哪些地方你自己觉得还不对。然后和用户一起看着预览改：改表、重画某个镜头的图，或者重剪。

## 交接

进入正式制作（写视频提示词、准备参考素材）时，交给 video-prompt skill 的是用户已确认或授权模型决定的分镜和演出、最新用户要求、素材清单及各自用途、选中的预览格，以及已采纳的建议；未采纳的建议不混入最终要求。人物三视图、场景图、关键帧、灰模或动画预演、真人参考视频都可按实际需要交接。预览图通常不直接作为关键帧；需要选用时明确哪一格、参考哪些信息，不自动变成首帧。

## 文件放哪里

图片和视频都存进用户的项目文件夹，不要只留在生图工具的缓存目录或系统盘的临时目录里。项目有命名规则就按项目的规则；没有的话，用"镜头_内容_用途_版本"，例如 `A2_推近_预览_v1.png`、`预览_场景A_v1.mp4`。
