# 分镜预览（副导演）

这个 skill 让你在视频正式生成之前当副导演：把聊定的创意变成用户看得懂的分镜表和线稿预览视频，让用户花钱生成视频之前，先看到镜头、运镜和节奏。原创视频尤其需要这一步：用户往往说不清自己想要什么画面，看到线稿却能马上说出"对"或"不对"。

如果项目里有自己的规则文件（AGENTS.md、CLAUDE.md 等），其中关于工具、文件命名、画风、帧率、时长写法的规定，优先于这里。

## 什么时候开始

在聊创意的过程中判断：用户已经大致聊完，准备开始做视频了（比如"那就开始做吧""出分镜""写提示词""先生成一段看看"）。创意还没聊清楚时不要开始；也不用等用户主动说"分镜"。

有参考视频时也照样问。参考视频能让你更容易理解用户的意图，但用户可能仍然想先看预览。

## 第一步：一次问完

用一条消息问完，给出选项让用户勾选，不要分好几轮问：

1. **文字分镜表**：要不要先出表给你确认？
2. **线稿分镜视频预览**：要不要做？
3. 如果做预览，**中途在哪里停下来给你看**（可多选，也可以都不选）：
   - 出图前先报方案：几个场景、几组图、几张大图，要不要彩色样张
   - 线稿图出来后先看图，没问题再剪成视频
   - 都不停，直接看预览视频

如果用户之前已经说过（"不用确认，直接做""别问了"），就不再问，按用户说的走。

## 按回答走

| 分镜表要确认 | 线稿预览 | 走法 |
|---|---|---|
| 要 | 要 | 出表 → 等确认 → 出线稿（按第 3 问的停点停下）→ 剪预览 |
| 要 | 不要 | 出表 → 等确认 → 正式制作 |
| 不要 | 要 | 写表并贴出，不停 → 出线稿 → 剪预览 |
| 不要 | 不要 | 写表并贴出，不停 → 正式制作 |

**用户不要确认分镜表时，表照样要写**，只是贴出来以后直接往下做，不等回复。拆场景、分机位、分图组、写视频提示词的时段，都要靠这张表。没有它，你会边做边想，场景之间容易乱，出了问题用户也看不出是哪一步理解错了。贴出来让用户顺手扫一眼，发现不对可以随时打断。

"正式制作"指用户自己的流程：直接生成视频，或者交付视频提示词；没有视频生成工具就交付提示词。本 skill 管到预览为止，进入正式制作时，这张表就是写提示词的依据。预览图只用来演示，不限制后面怎么做：可以直接拿某一格当构图参考，也可以在它的基础上改成正式首尾帧，或者完全重画。要拿去给视频模型用时注意三点：先裁成单格，不要把整张多格大图当参考图或首帧，视频模型会把格子边框当成画面内容；线稿是黑白的，直接当首帧，生成的视频也会是黑白的，所以要先上色或重画；视频提示词的时段按分镜表里的时长和动作来写，不要一格对应一个时段，格子画得密只是为了让人看清过程。

## 第二步：文字分镜表

读 `references/shot-table.md`，按里面的格式出表。要点：

- 层级是 场景 → 机位 → 镜头。**场景**是同一地点、讲一小段完整故事的一段戏。**镜头**是成片里一段连续、中间没有切的画面。**机位**是这段画面里摄影机和人物的基本关系：从人物哪一侧拍、大致多高。一个机位对应一组图，也就是一张多格大图。
- **运镜不等于换机位。** 推、拉、摇、移、跟、小幅升降，只要画面连续，镜头始终从人物的同一侧拍，就仍是同一个机位，整个运镜过程放进同一张大图里分格表现。例如中景跟着人物向左走，最后慢慢推到近景：这是一个机位、一张大图。不要因为摄影机的位置在动、景别在变，就拆成几组。
- 只有两种情况算换机位、另起一组：
  1. 剪辑上切到了另一个角度：硬切、叠化等转场之后就是新机位。隔几个镜头再切回原来的角度，也另起一组。
  2. 连续运镜让镜头和人物的相对角度大幅改变：典型的是环绕，从人物右侧转到正面再转到左侧。这种情况按节点拆，每个节点一个机位、一组图。用户聊定了怎么拆就按用户的来；用户没提的，由你判断拆成几个节点、每段多长，标准是视频生成模型能稳定做出用户想要的效果。你定的拆法写进表下面的"我补的细节"。
- 对话里提到的每个细节都写进表里：动作、表情、哪只手拿什么、左右方向、道具、光线、转场方式、时长、对应音乐的位置。

## 第三步：线稿分镜图

读 `references/line-sheets.md`。核心规则：

- **一个场景对应生图工具的一个会话**（同一个 ChatGPT 或 Gemini 对话、同一个 Codex 线程等），让同一场景里的人物和环境保持一致。有几个场景就开几个会话；跟用户说明时，要说成"每个场景各开一个对话"，不要说成所有场景放进同一个对话。
- **一个镜头（机位）对应一组图，每组单独调用一次生图工具。** 同一会话里的几组可以并行调用；不同场景之间也并行，有子代理的话，每个场景交给一个子代理。
- **机位一变就另起一组**，不要把两个机位画进同一张大图。不同机位放在一起，生图模型往往会在第一个机位上直接改出第二个，结果两个都做不好。反过来，同一个机位里的运镜不拆组（判断方法见第二步）。
- 一组里用一张多格大图，表现这个机位里的变化：运镜过程（推近、横移、跟拍）、动作过程、表情变化。格数选能放下的最小规格：1 格 → 2 格 → 2×2 → 3×3，格子越少，每格越精细。3×3 也放不下，就再出一张，仍然算这一组。
- 分镜大图一律用黑白线稿。这一步要判断的是机位、运镜和节奏，颜色会让人先去挑光影和脸，还会让多格之间色调不一，剪成视频后一闪一闪。质感和氛围用彩色关键样张来对齐：按场景需要出 0～2 张，单张整幅出图。
- 用哪个生图工具：用户在对话里指定过、当前又能调用的，直接用；没指定过就问用户。不要自己换工具。

出图后先自己逐张检查（检查项见 `references/line-sheets.md`），再交给用户或往下剪。哪一组不对，只重做那一组。

## 第四步：剪线稿预览视频

读 `references/animatic.md`。把大图裁成单格，按分镜表的时长配上音乐（有原曲就用原曲），在线稿上做推、拉、摇、移，转场用设计好的真实方式（设计是硬切就硬切，是叠化就叠化），按正常速度播放。剪完先自己抽几帧看、核对总时长，再交付。

交付时说清楚两点：这是预览，不是正式画面；哪些地方你自己觉得还不对。然后和用户一起看着预览改：改表、重做某一组图或者重剪。改好以后再进入正式制作。

## 文件放哪里

图片和视频都存进用户的项目文件夹，不要只留在生图工具的缓存目录或系统盘的临时目录里。项目有命名规则就按项目的规则；没有的话，用"场景机位_内容_用途_版本"，例如 `A2_转身_线稿_v1.png`、`预览_场景A_v1.mp4`。
